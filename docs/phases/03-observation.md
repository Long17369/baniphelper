# 阶段三 观测能力

## 1 目标与范围

把「谁连了谁、传了多少」变成可查询的记录：连接枚举、TCP 与 UDP 流量统计、
记录去重与聚合、批量落库与保留期、按需降频。

本阶段**不做封禁**，也不做界面。它与阶段二使用完全不同的数据源，因此可以并行推进。

## 2 前置条件

| 项 | 状态 |
| --- | --- |
| 阶段一完成 | 接口已冻结，数据库子系统可用 |
| 统计路线 | 见 [architecture.md](../architecture.md) 第 5.1 节 |
| 两个待实测点 | 扩展统计对老连接的有效性、事件是否含进程标识 |
| 平台相关实现 | 枚举与统计经 `IConnMonitor`、`ITrafficStats`、`ISessionMonitor` |

## 3 步骤清单

| 步骤 | 内容 | 产出物 | 验收 | 依赖 | 并行 |
| --- | --- | --- | --- | --- | --- |
| S3.1 | 连接枚举：TCP 与 UDP 端点表的 IPv4 与 IPv6 版本，并映射到进程 | 枚举模块 | 连接清单与系统工具对照一致 | S1.2 | 是 |
| S3.2 | TCP 流量统计：先启用扩展统计再读取，并验证对已建立较久的连接是否立即有效 | 统计模块 | 数字与持续传输的实际增量相符 | S3.1 | 是 |
| S3.3 | 事件订阅：订阅网络事件提供程序，实测其 UDP 事件是否携带进程标识 | 事件模块与实测结论 | 实测给出明确结论，不留猜测 | S1.2 | 是 |
| S3.4 | UDP 流量统计：按 S3.3 结论落地；若不含进程标识则降级为按流统计不统计字节 | 统计模块扩展 | UDP 流量可见，或明确标注为不可归属 | S3.3 | 否 |
| S3.5 | 去重与聚合：新出现的组合落库，已存在只更新计数与时间 | 记录模块 | 重复连接不产生重复行 | S3.1 | 是 |
| S3.6 | 批量写入与保留期：WAL 模式、批量事务、按天清理、总量上限 | 存储优化 | 高频写入下占用可控，表不无界增长 | S3.5 | 是 |
| S3.7 | 生命周期与降频：界面关闭时降频或暂停采集，恢复时补齐 | 调度模块 | 无界面时占用接近零 | S3.2 | 是 |
| S3.8 | 精度核对：与系统工具对照，明确口径差异并记录以谁为准 | 核对记录 | 差异有解释，不是「差不多」 | S3.2、S3.4 | 否 |

## 4 并行编组

| 编组 | 步骤 | 并行安全性依据 |
| --- | --- | --- |
| A | S3.1、S3.3 | 两条独立数据源，代码路径不重叠 |
| B | S3.2 与 S3.5、S3.6 | 都依赖 S3.1，但分别负责采样与落库，可并行 |
| C | S3.4 | 必须等 S3.3 的实测结论，不可先假设 |
| D | S3.7、S3.8 | 收尾步骤，依赖主干能力 |

## 5 阶段验收

1. 连接清单与系统工具对照一致，且同时覆盖 IPv4 与 IPv6
2. TCP 流量数字与持续传输的增量相符
3. UDP 流量的可行性有明确实测结论，落地方式与该结论一致
4. 记录表在长时间运行下不无界增长
5. 无界面时可观测占用接近零
6. 两种来源的口径差异已记录，并明确以哪个为准

## 6 风险与对策

| 风险 | 对策 |
| --- | --- |
| 扩展统计对老连接可能拿不到累计值 | 先实测；若确认不可用，则在连接首次发现时立即启用，并对更早的连接标注为「自启用起计数」 |
| 事件可能不含进程标识 | S3.3 必须先给结论；降级方案为只统计流数与地址，字节数标注为不可用 |
| 事件洪泛导致占用升高 | 订阅时使用关键字与级别过滤，避免全量事件进入用户态 |
| 记录写入放大 | 批量事务与保留期同属 S3.6，一次做完，不留到后期 |

## 7 交付物清单

- 连接枚举模块
- TCP 统计与 UDP 统计
- 事件订阅模块与实测结论记录
- 记录落库与保留期机制
- 精度核对记录
