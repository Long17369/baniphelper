# 阶段六 WebUI

## 1 目标与范围

提供一个本地网页界面，用于远程或无界面场景：全部配置项可改、规则与记录可管、
写入与桌面界面共用同一个核心。

本阶段**排在 GUI 之后**。理由是：界面已能满足桌面使用，网页端的价值在于远程与自动化。

## 2 前置条件

| 项 | 状态 |
| --- | --- |
| 阶段五主体完成 | 设计系统与核心交互已定型，可对齐 |
| 阶段四完成 | 全部配置项已确定，才谈得上「配置全量可改」 |
| 缺失模块 | HTTP 服务模块当前未安装，需要补装，见 S6.1 |

## 3 步骤清单

| 步骤 | 内容 | 产出物 | 验收 | 依赖 | 并行 |
| --- | --- | --- | --- | --- | --- |
| S6.1 | 补装 HTTP 服务模块并通过在线安装器纳入工程，验证可链接 | 构建配置更新 | 工程能链接该模块并成功启停服务 | S1.1 | 否，最先 |
| S6.2 | 本地服务与路由：绑定地址与端口可配置，端口被占用时递增 | 服务模块 | 服务可启停，端口冲突可自动规避 | S6.1、S1.5 | 否 |
| S6.3 | 鉴权与绑定策略：默认仅本机、令牌鉴权、开放局域网时强制令牌 | 鉴权模块 | 无令牌的非本机请求被拒绝 | S6.2 | 是 |
| S6.4 | 配置接口：全量配置项的读取与修改，含校验与变更通知 | 配置接口 | 网页端改配置后核心立即生效 | S6.2 | 是 |
| S6.5 | 业务接口：规则增删改查、连接记录查询与导出、目标进程列表 | 业务接口 | 接口能力与桌面界面一致 | S6.2 | 是 |

## 4 并行编组

| 编组 | 步骤 | 并行安全性依据 |
| --- | --- | --- |
| A 基座 | S6.1 到 S6.2 | 服务不可用则其余无从谈起 |
| B 接口 | S6.3、S6.4、S6.5 | 三组接口代码分离，共享 S6.2 的框架 |
| C 前端 | S6.6 | 可用模拟数据先行，不必等接口完成 |
| D 收尾 | S6.7、S6.8 | 分别在加固与一致性层面收口，两者可并行 |

## 5 阶段验收

1. 服务可启停，端口冲突能自动规避
2. 默认仅本机可访问，开放局域网时必须携带凭据
3. 桌面界面的全部配置项都能在网页端修改，且改动立即生效
4. 规则与记录可在网页端完成增删与查询
5. 两侧同时操作不产生冲突状态
6. 加固清单逐项验证通过

## 6 风险与对策

| 风险 | 对策 |
| --- | --- |
| 双写导致状态不一致 | 单一数据源，写操作统一走核心接口层，两侧只做展示与转发 |
| 服务意外暴露 | 仅本机绑定写死为默认值，开放局域网属于显式操作并在界面上警示 |
| 前端与桌面端视觉分裂 | 复用同一套设计令牌，颜色与间距不允许两侧各写一份 |
| 模块补装影响构建链 | S6.1 单独成步，先保证构建稳定再写业务 |

## 7 交付物清单

- 构建配置更新（HTTP 服务模块）
- 本地服务与路由
- 鉴权与绑定策略
- 配置、规则、记录三类接口
- 前端三页
- 安全加固清单与验证记录
- 两侧状态一致性方案
