# 阶段四 安全阀与自我保护

## 1 目标与范围

让「封错」与「封死自己」这两类事故不可能发生：白名单模式、最小可用放行清单、
超时自动回滚、自我保护、危险操作审计、故障演练。

本阶段是 MVP 闭环的最后一环，也是**唯一一个把安全当作交付物**的阶段。

## 4 并行编组

| 编组 | 步骤 | 并行安全性依据 |
| --- | --- | --- |
| A 安全链 | S4.1 到 S4.2 到 S4.3 | 安全语义必须一次做对，不允许拆分后各自验收 |
| B 独立 | S4.4、S4.5 | 分别针对自我保护与归属判据，与安全链无耦合 |
| C 收尾 | S4.6、S4.7 | 依赖 S4.3，两者彼此独立可并行 |

## 5 阶段验收

1. 切换白名单模式后，只有放行清单内的通信可用，且系统网络未中断
2. 未在倒计时内确认时，配置自动还原且不残留阻断规则
3. 任何规则组合都无法切断自身进程
4. 启动时只清理自家过滤器，不触碰其他工具
5. 危险操作均有二次确认与审计记录
6. 三类故障演练全部通过
7. 宽条件达到两个及以上的规则被识别为高风险，下发前强制二次确认
8. 二次确认界面能显示预估影响，且预估与实际命中基本一致
9. 演练模式对任意规则可开启，期间只记录不下发，可随时转正或取消

## 6 风险与对策

| 风险 | 对策 |
| --- | --- |
| 把自己彻底锁死 | 超时回滚是硬性要求，不可配置为关闭；演练必须包含「故意不确认」这一项 |
| 放行清单遗漏导致网络不可用 | 清单按「最小可用网络」逐项验收，每一项都要能说出断开它的后果 |
| 回滚本身失败 | 回滚走与正常配置不同的路径，只做删除不做新增，缩小失败面 |
| 清理误伤他方过滤器 | 归属判据只用自有 provider 与 sublayer，并安排一次带干扰源的演练 |
| 取反条件让规则变宽而用户没察觉 | 宽条件必须被显式标记，且规则要渲染成一句中文供审阅 |
| 预估影响算不准导致用户误判 | 预估给数量级并标注依据即可，宁可显示区间，也不要给一个看起来精确的假数字 |
