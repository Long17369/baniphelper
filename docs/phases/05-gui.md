# 阶段五 GUI

## 1 目标与范围

做出一套**可用的、好看的**桌面界面，让全部日常操作都能在界面内完成：
选目标进程、看连接记录、管规则、看流量、操作白名单模式。

技术选型为 Qt Quick，理由与替代方案见 [architecture.md](../architecture.md) 第 2 节。

## 2 前置条件

| 项 | 状态 |
| --- | --- |
| 阶段一完成 | 托盘外壳与冻结接口可用 |
| 界面依赖 | 只允许依赖总纲第 3.2 节冻结的接口，禁止直接访问数据库与过滤器引擎 |
| 可并行性 | 只依赖阶段一，因此可与阶段二、三、四并行推进 |

## 4 并行编组

| 编组 | 步骤 | 并行安全性依据 |
| --- | --- | --- |
| A 基座 | S5.1 到 S5.2 到 S5.3 | 后续页面都依赖主题与窗口外壳，必须先行 |
| B 页面 | S5.4、S5.5、S5.6、S5.7 | 四个页面代码分离，仅共享 S5.3 提供的骨架 |
| C 交互 | S5.8、S5.9 | 分别依赖状态栏与窗口外壳，彼此独立 |
| D 收尾 | S5.10 | 必须在页面全部完成后进行 |

## 5 阶段验收

1. 规划中的日常操作都能在界面内完成，无需命令行
2. 界面状态与核心状态一致，不出现界面显示已封禁但实际未生效的情况
3. 记录页在上万行时仍可流畅滚动
4. 无界面时占用接近零，符合阶段三的降频要求
5. 视觉走查清单全部通过
6. 所有错误都有明确提示，不出现静默失败

## 6 视觉验收要点

1. 深色主题下正文与背景的对比度满足可读性要求
2. 空态、加载态、错误态三种状态都有对应界面，不出现空白页
3. 长列表滚动无撕裂，行选中状态清晰
4. 图标风格统一，不混搭多种风格
5. 窗口缩放时布局不错位，最小尺寸下不出现控件重叠

## 7 风险与对策

| 风险 | 对策 |
| --- | --- |
| 提权进程下调试体验差 | 界面逻辑与核心逻辑解耦，界面可用模拟数据独立运行，减少对提权的依赖 |
| 接口未冻结导致界面返工 | 界面只依赖冻结接口，违反该约束的代码在评审阶段直接打回 |
| 追求美观拖慢进度 | 设计系统先行，页面阶段只做组合与微调，不逐页重造样式 |
| 记录量大导致界面卡顿 | 表格必须虚拟化，增量加载属于 S5.5 的验收项 |
